# UI and implementation audit

Audit mode: AFTER. This report records findings for review; do not change the findings until the user selects their numbers.

1. **Critical — finance data is outside archive export/restore.** The new `finance_` records are initialized through the experimental upgrade path, while Hall's existing archive round trip only serializes its archive schema. Enabling `FINANCE_EXPERIMENTAL` on a live installation could create user data that is absent from backup and restore. Keep the feature disabled in production until finance backup/restore and round-trip coverage are complete.

2. **Major — the requested Savers/TrackMoney parity is incomplete.** Planner notes, reminders, scheduled tasks and delivery tracking, bot endpoints, profile pictures, imports, and group/member administration are not included in this slice. The implementation plan records the gaps in its Work in progress section.

3. **Major — visual and keyboard behavior has not been reviewed in a real browser.** The route returned HTTP 200 during a local smoke check, but the in-app browser bridge could not initialize. Layout at narrow widths, focus movement, screen-reader announcements, and the wallet edit/delete flow therefore remain unverified. `FinanceWorkspace.module.css` also has no explicit `:focus-visible` treatment; the current appearance relies on browser defaults.

4. **Major — concurrency evidence is limited to PGlite.** Ledger tests exercise concurrent withdrawals and row-lock paths in PGlite, but no disposable PostgreSQL instance was available for validating production row-lock semantics and transaction behavior.

5. **Moderate — wallet mutations are available to every group member.** Wallet create, edit, and empty-wallet deletion check membership but do not require owner/admin role, while budget, source, and invitation management do. Confirm that this permission difference matches the intended shared-wallet roles.

6. **Moderate — group and source lifecycle controls remain absent.** Managers can create sources but cannot rename/archive them, and there are no endpoints for role changes, member removal, invitation revocation, or group deletion. These controls matter for cleaning up mistakes and managing access after sharing an invite.
